## 背景

AiToEarn 是个开源的 AI 内容营销平台，宣称能自动生成、分发内容。
我想的是很实际的一件事：**能不能把它跑在本机，当成一个自己的内容工作台**，顺便接上本地的生图服务。

## 方案

官方支持 Docker 部署，我这边环境是 WSL2 里的 Ubuntu 24.04。
选择整套 Compose 起、不动代码，先确认"能跑"，再考虑"能用"。

技术栈大概是 Next.js（Nx 管理的 monorepo）+ MongoDB + 若干 worker 容器。

## 过程

```bash
git clone <repo> && cd AiToEarn
docker compose up -d
docker compose ps        # 7 个容器，全部 healthy
```

起来之后前端能访问、能建内容、能上传图片和提示词。
但**真正点"生成"的时候，AI 不动**。

## 踩坑

| 现象 | 原因 | 解法 |
| --- | --- | --- |
| 传了图和提示词，点生成没反应 | 不是代码问题，是上游模型余额不足 | 账户余额 $0.001338，单次调用要 $0.004180 |
| 换成免费模型后能跑 | 平台支持指定模型 | 生成用 `deepseek-v3.2(free)`，出图用 `qwen-image(free)`，整条链路成本 $0 |
| 报错信息看不出是额度问题 | 失败被包装成通用的任务失败 | 去后端日志里翻上游返回才看到额度报错 |

这条坑值得单独说：**AI 应用里"没反应"十次有八次不是代码错，是额度、超时或者模型名写错了。**

## 结果

跑通了：7 个容器稳定，能生成草稿，换成免费模型后全链路零成本。

但说实话——**能跑 ≠ 有用**。

- 维护成本：7 个容器 + 一个数据库，占内存不少
- 内容质量：自动生成的东西还得人工过一遍，省不了太多事
- 我的真实需求（本机生图 + 简单排版）其实几个脚本就够了

所以"好了，先不研究这个了"，先放着。真正会长期用的，是下面那套公众号工作流。
