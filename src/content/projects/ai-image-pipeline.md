## 背景

用 AI 生图一段时间后，最大的问题不是模型不好，而是**流程太脏**：

- 好用的提示词写在聊天记录里，第二次想复用要找半天
- 同一个风格要出 10 张，只能一张一张点
- 出完的图散在下载目录，按 `image_(1).png` 命名，过一周完全不知道哪张是什么

## 方案

拆成三段，每段都能单独用：

```
模板库（JSON） → 批量渲染（Python） → 出图 + 归档
```

**模板库**就是一堆带变量的字符串：

```json
{
  "id": "product-hero",
  "prompt": "{subject}，{lighting}，{style}，超高细节，{ratio} 构图",
  "defaults": { "lighting": "柔光侧逆光", "style": "商业摄影质感" },
  "ratio": "3:4"
}
```

**批量渲染**：一行命令读模板 + 变量表，生成 N 组请求：

```bash
python gen.py --template product-hero \
  --vars vars.csv --count 3 --out ./out
```

**归档**：`out/<日期>/<模板>/<序号>_<短哈希>.png`，同时写一份 `meta.json` 存下完整提示词和参数。

## 过程

最麻烦的其实不是调 API，是**统一不同渠道的参数**。不同服务商的尺寸写法不一样：

| 渠道 | 尺寸参数 | 参考图 |
| --- | --- | --- |
| OpenAI 兼容 | `size: 1024x1024` | `/images/edits` 表单 |
| 某系列模型 | `aspect_ratio: 3:4` + `image_size` | JSON 数组传图 |
| 另一家 | 只能文生图 | 不支持 |

包里做了一层适配，上层只写「我要 3:4、2K」，转换交给适配器。
这样以后接新渠道，只用加一个几十行的文件。

## 踩坑

| 现象 | 原因 | 解法 |
| --- | --- | --- |
| 偶尔返回的图是空白 | 上游偶发失败但返回 200 | 加尺寸/熵校验，检测到空白自动重试 |
| 一次请求 10 张全挂 | 并发打太高被限流 | 信号量限制并发为 2，指数退避重试 |
| 费用对不上 | 不同尺寸价格不一样，没记录 | meta.json 里存 `size` 和 `cost`，月底跑一次统计 |
| 中文提示词偶尔被截断 | 某些渠道对长 prompt 静默截断 | 提交前按渠道上限做分段检查 |

## 结果

现在出图基本是「填一张变量表 → 跑一条命令 → 喝口水回来收图」。

- 单张成本：约 0.1~0.4 元，取决于尺寸和模型
- 一个月总花费：86 元（含试错废片）
- 真正省下的：找提示词的时间，从"找不到"变成"选中模板"

**结论**：值得。模板库是这套东西里最值钱的部分，它把「一次好运气」变成了「可重复的输入」。
